# AbsoluteCare: Three-Audit Report and Phased Remediation Plan

- **Date:** 2026-10-28
- **Repository:** AbsoluteCare (backend Express/Mongoose, frontend React 19/Vite)
- **Scope:** over-engineering (ponytail), folder architecture, UI and visual anti-slop, design craft
- **Mode:** report only. No source files were modified by this audit.
- **antislop mode:** `antislop active: during (session override)` for any future edit work driven by this report. Findings below are written so they can be executed in during mode.

---

## 0. How to read this

Each phase is a self-contained unit of work with its own goal, findings, tasks, acceptance criteria, effort and rollback. Phases are ordered by dependency, not by severity: Phase 1 must land before Phase 2 deletes anything, because several deletions depend on where code ends up. Phase 3 and Phase 4 can run in parallel with Phase 2 on a second branch if two people are working.

Finding IDs are stable (`S-` structure, `P-` ponytail, `U-` UI, `D-` design craft) and are indexed in Appendix A. Every finding cites a real path and, where known, a line.

Nothing here is a correctness or security review. Appendix D lists the correctness-shaped things found in passing and deliberately not fixed.

## 1. Executive summary

| Audit                       | Verdict                                           | Headline                                                                                                                                                                                                                                |
| --------------------------- | ------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Folder architecture         | **Failing at the edges, sound at the core**       | 1 file holds 38% of all frontend CSS lines; 4 append-only sidebar style layers; 3-file context pattern with case-only filename collisions; loading and skeleton systems duplicated twice over                                           |

**Net achievable reduction:** roughly `-3,400` lines of CSS/JS, `-25` files, `-2` dependencies, without removing a single user-facing feature. The one user-facing feature that should be _removed_ is the admin profile page, because it has no feature behind it yet.

Three things are already good and should not be "fixed":

1. The palette is branded and restrained (Phase 3.3, `U-17`).
2. Glass, glow, radius and shadow are all inside the antislop dose caps (`U-18`).
3. `prefers-reduced-motion` is handled in 15 blocks, and `:focus-visible` in 55 rules. That is above the norm for a project this size.

## 3. Design Read (required before Phase 3 and Phase 4)

> Reading this as: a clinic scheduling portal plus a public clinic landing page, for patients in Malaybalay City and clinic staff, in a warm editorial clinical language (mint, paper, deep teal, chartreuse accent, Fraunces display over DM Sans), with dial **ENERGY 2 / RHYTHM 2 / MOTION 1**.

Justification, one line each, as R-31 requires:

- **ENERGY 2, not 3:** the audience is patients in pain or parents of children in therapy. The landing page already speaks quietly and refuses the hype register. Keep that.
- **RHYTHM 2, not 3:** the landing page does vary composition (split hero, 4-up benefits, 2-up service cards, 4-step process, map split). The dashboards do not vary at all, and that is the gap Phase 4 closes.
- **MOTION 1:** the product is a scheduling tool used repeatedly. No scroll reveal, no parallax, no entrance choreography. Motion stays where it already is: loaders, progress, press feedback.
- **Signature element (choose one and protect it):** the CSS-drawn therapy room in the hero (`sun-disc`, `therapy-chair`, `plant`, `room-line`, `hero-note`). It is specific to this clinic and cannot be swapped into another product. That is the identity motif. The eyebrow dot and the arrows are not.

If a `DESIGN.md` is created in Phase 3, it should record exactly this block plus the palette and type scale, and nothing more.

Notes that keep this honest with the skill's thresholds:

- Depth stays at `src/features/<feature>/<kind>` (4 levels max). No deeper.
- `shared/` entry rule: a module qualifies only with 3 or more consumers. `format/` qualifies. `ToastProvider` stays put: it is a single consumer wiring file.
- `backend/` gets the same treatment only where it already hurts: split `settingsController.js` (790 lines) into `settingsReadController` and `settingsWriteController`, or extract the integration credential handlers into `controller/integrationController.js`. Do not restructure the rest.

## Phase 4: Design craft

**Goal:** turn a system that works into a system with a point of view, without adding decoration. This is the phase where the loaded design skills (frontend-design, emil-design-eng, apple-design, animate, web-design-guidelines, antislop-human, antislop-layoutmobile, antislop-copywriting) actually change the output.

**Effort:** 3 to 4 days. **Risk:** medium. **Depends on:** Phase 3.

### 4.1 Typography

- [ ] **D-01 Tabular figures** everywhere numbers are compared (stat cards, payments, durations, table columns). Zero currently exist.
- [ ] **D-02 Font delivery**: preconnect plus `link` tags or self-hosted WOFF2; `font-display: swap`; consider dropping Fraunces weights 500 and 600 down to the single weight actually used by headings. Verify which weights are used before cutting.
- [ ] **D-03 Type scale as tokens**: the stylesheet sets font sizes in raw px across 1,883 rules. Introduce `--text-xs` through `--text-display` once, and use them for the four shared surfaces first (`page-header`, `dashboard-card`, `staff-table`, `stat-card`). Do not attempt a global sweep.
- [ ] **D-04 Size-aware tracking**: large headings want slightly negative letter-spacing, body near zero. The stylesheet currently uses a fixed `letter-spacing: 0.08em` on eyebrows (fine) and default tracking on display headings (not fine at 40px+).

### 4.2 Motion

- [ ] **D-05 Kill the decorative loops.** `logo-breathe` (2.4s), `loader-breathe` (2.4s) and `sidebar-shimmer` (1.5s) run forever with no state behind them. `sidebar-shimmer` is the clearest R-19 violation: a shimmer on idle chrome. Spinners and skeleton shimmers stay, they are functional.
- [ ] **D-06 Standardize easing.** Add `--ease-out: cubic-bezier(0.23, 1, 0.32, 1)` and `--ease-in-out: cubic-bezier(0.77, 0, 0.175, 1)`, and replace the 4 `transition: all 0.15s ease` declarations (`index.css:9851, 10024, 10056, 10163`) with named properties, `ease-out`, 150 to 200ms.
- [ ] **D-07 Press feedback.** 12 `:active` blocks exist, so this is nearly there. Ensure every button, row and card link has `transform: scale(0.97)` on `:active` at 100 to 160ms, and that the transform is on a compositor-friendly property.
- [ ] **D-08 No motion for repeated actions.** Table sorting, pagination, tab switching and row selection are used dozens of times a day. They get instant state, plus a focus-visible ring. No fade, no slide.
- [ ] **D-09 Reduced motion coverage.** 15 blocks exist. Audit that every `@keyframes` and every `transition` that moves something is covered, and that reduced motion keeps opacity changes while removing transform movement.

### 4.3 Accessibility and states (antislop-human, web guidelines)

- [ ] **D-10 The 9 `outline: none / 0` declarations**: `index.css:929, 1505, 3411, 6327, 10093, 10838, 10938, 11001, 12070`. Each must have a `:focus-visible` replacement on the same selector. 55 focus rules exist, so most are fine; verify the 9 and fix the ones that are not.
- [ ] **D-11 Contrast audit of the token pairs**, computed not eyeballed: `--ink-soft #537175` on `--paper #f4f8f5`, `--ink-soft` on `--white #fffefa`, `--chart-*` on white, and the status badge pairs (`--status-pending-text #92400e` on `#fef3c7`, and the other four). Use the contrast checker; report the ratio for each.
- [ ] **D-12 Status by more than color.** Status badges already carry text labels (`Pending`, `Confirmed`), which passes. Keep that; do not add color-only dots.
- [ ] **D-13 ARIA on the hero visual.** `<div className="hero-visual" aria-label="A calm therapy room">` puts a label on a non-semantic div with no role. Either add `role="img"` or mark it `aria-hidden="true"` (it is decorative CSS art).
- [ ] **D-14 Dialog behavior.** `CredentialDialog` and the settings modals must close on Escape, trap focus, and return focus to the trigger. Verify one dialog end to end rather than all of them.
- [ ] **D-15 Long content.** Confirm table cells truncate with a title attribute (the pattern exists in `AdminPrimitives` `StackedCell`), and that flex children have `min-width: 0` where text truncates.
- [ ] **D-16 Unsaved-change guard** on the 2,082-line settings page, which has many fields and no `beforeunload` handling.

### 4.4 Responsive and layout (antislop-layoutmobile)

- [ ] **D-17 Collapse the 16 breakpoints to 4 documented states**: phone (<600), tablet (600 to 900), small laptop (900 to 1100), desktop (>1100). Document each in `responsive.css` with the content reason, then move rules into the nearest state. This is a ratio change, not a rewrite: fix the ones that disagree.
- [ ] **D-18 Verify the 600 to 900 band**, which currently has the thinnest coverage, on the admin dashboard, payments table and settings page.
- [ ] **D-19 Tap targets**: confirm 44px minimum on the sidebar toggle, row actions menu, pagination and the notification bell. The row action icon buttons (`Eye`, `Pencil`, `MoreHorizontal` at 16 to 17px) are the likely failures.
- [ ] **D-20 Fixed chrome must not cover content**: the staff topbar is 72px fixed (`--dashboard-topbar-height`) and the sidebar is 246px. Confirm `scroll-margin-top` on anchored headings and that the mobile drawer does not trap the last row of a table under the bar.

### 4.5 Performance felt as design (emil-design-eng, web guidelines)

- [ ] **D-21 Route-level code splitting.** One 1,145 kB chunk ships the landing page and 40 protected routes to every visitor, including the patient booking flow. Lazy-load `staff/*` and `pages/staff/admin/*` (10 modules), which no patient route needs. Measure before and after with the build output; the target is an initial chunk under 400 kB.
- [ ] **D-22 Loading perception.** The auth context already enforces a 400ms minimum loader delay (`AuthContext.jsx`), which is the right instinct. Extend the same deliberate minimum to dashboard skeletons so the shell does not flash.
- [ ] **D-23 Image dimensions.** `logo2.png` is 306 kB and `logo-full-dark.png` 266 kB. Serve a smaller variant with explicit `width`/`height`, and use `loading="lazy"` below the fold.
- [ ] **D-24 Verify the landing page's LCP element** (the hero heading or the CSS illustration) and make sure nothing above the fold is blocked by the font `@import` from `U-16`.

### 4.6 Copy (antislop-copywriting)

The landing copy is unusually good for a generated project: specific, local, no buzzwords, no fake proof. Protect it.

- [ ] **D-25** Replace only the generic CTAs (`U-11`), and leave the headlines ("Start moving toward your better day.", "Four small steps. Less to think about.") alone. They are specific and they carry voice.
- [ ] **D-26** Standardize the apostrophe form: the codebase mixes `We’re` (curly) with `We're` in JSX. Pick curly for rendered prose, straight for code.
- [ ] **D-27** Audit `Don't have an account?` style strings against the interface's voice: active, second person, sentence case. The auth copy already does this well.
- [ ] **D-28** Fix the duplicated intent between "Book an appointment" and "Create your account" on the same page (the footer link says the latter, the hero says the former, both go to `/signup`).

### Acceptance

- Contrast ratios recorded for every token pair, all meeting 4.5:1 (normal) and 3:1 (large/non-text).
- `transition: all` count is 0; `font-variant-numeric` count is above 0; infinite decorative animations reduced to spinner and skeleton only.
- Initial JS chunk under 400 kB with route-level splitting.
- No motion on sort, pagination, tabs or row selection.
- The 4 breakpoint states documented and exercised.

## Appendix D: Out of scope (correctness and security leads)

Found while reading, deliberately not fixed here. They belong in a normal review pass.

1. `authController.js` and `emails/templates/index.js` both export `resetPassword`. If any file ever imports the wrong one, the failure is silent.
2. `app.js:66-67` mounts `settingsRoutes` at both `/settings` and `/admin/settings`. Verify that both paths enforce the same authorization, rather than one being a legacy alias with weaker checks.
3. `secretBox.js` falls back from `CREDENTIAL_ENCRYPTION_KEY` to `GOOGLE_CALENDAR_ENCRYPTION_KEY` to `JWT_SECRET`. Silently rotating the JWT secret then makes stored credentials undecryptable. That may be acceptable, but it should be a documented decision with a startup warning.
4. `restartService.js` calls `process.exit(0)` after closing the server and the database, gated behind `ALLOW_SELF_RESTART` and supervisor detection. Confirm that a credential save cannot trigger it in a single-instance deployment without a supervisor, where the process would simply stop.
5. `providerValidation.js` performs live provider calls from an admin action, with a 5-per-5-minutes limit per admin. That is reasonable, but the limit is in-memory and per process, so it resets on restart and does not hold across instances.
6. `AdminPrimitives.RowActions` opens a menu on click with no outside-click or Escape dismissal. It is a correctness/accessibility issue rather than slop, and it overlaps D-14.
